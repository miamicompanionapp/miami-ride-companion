TEST SUITE & TAGS (Playwright)
------------------------------
Run all with `npm test`. TAGGED for fast targeted regressions:

    npm run test:index     # whole passenger app (index.html)
    npm run test:games     # all 5 games (logic + i18n + flows)
    npm run test:editor    # driver dashboard (editor.html)
    npm run test:backend   # Cloudflare Functions pure logic
    npm run test:weather / test:content / test:phone / test:rest  # index sub-areas
    npm run test:feedback  # ride feedback feature (tests/feedback.spec.js)
    npm run test:smoke     # fast critical-path subset
    npm run test:negative  # all failure-path tests
    npm run test:i18n      # translation / language-switch tests
    npm run test:units     # all in-browser pure-function unit tests

Tag taxonomy:
  PAGE  : @index @editor @games @backend  (+ sub-areas @weather @content @phone @rest @feedback)
  TYPE  : @unit (pure-fn) · @negative (failure paths) · @smoke · @i18n

Layout:
  - Pure logic lives in *-units.spec.js + backend.spec.js (base @playwright/test
    runner — CDN blips can't fail a pure assertion).
  - Behavioral E2E flows use ./fixtures, which FAILS on any console/page error —
    that strict gate catches silent breakage; keep it on flow specs only.
  - backend.spec.js imports functions/api/* helpers directly (test-only `export {…}`).
    No live network.

Freshness canary: tests/passenger.spec.js "published events are all upcoming"
goes RED once published events age past today — intentional, nudges a re-fetch
+ "Remove past" in the editor.

ARCHITECTURE NOTE
-----------------
Single-file index.html (~3200+ lines including CSS + JS) and editor.html (~1500
lines). No build step. SW caches files verbatim.

Decision (2026-05-28): KEEP the monolith. Don't migrate to a framework.
If/when navigation pain forces a refactor: split into native ES modules (no bundler)
before reaching for React/Vue/Svelte/Vite. The cost of a build pipeline hugely
outweighs the benefit at this scale.

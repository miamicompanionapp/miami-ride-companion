  1. [X] #84  Offline event-image pre-caching was silently broken for every passenger
       (surfaced by #83's investigation, fixed separately): prewarmEventImages()
       (public/index.html) used a default cors-mode fetch() against soulofmiami.org,
       which sends no Access-Control-Allow-Origin header, so the fetch was always
       blocked by the browser and silently swallowed by the existing try/catch —
       passengers still saw images fine online (<img src> doesn't need CORS), they
       just never got cached for offline/no-signal use in the car. Fix: switched to
       `fetch(url, { mode: 'no-cors' })`, which returns a valid "opaque" response
       Cache API can store (can't inspect status/body, but that's fine — the whole
       point is just to have it available offline later). Verified manually: 69
       event images now land in the 'miami-event-images' cache with 0 console
       errors (previously 0 images ever cached). Added a regression test
       (tests/content.spec.js, "Offline event-image pre-caching") that stubs the
       image host WITHOUT a CORS header (mirroring the real soulofmiami.org
       behavior) and asserts caching still succeeds. DONE 2026-07-19 (SW v1.92.0).
  1. [X] #83  Test suite had "random" failures — a different set of tests failed on
       every `npm test` run (20 failed, then 27, almost no overlap), always with
       `console.error: Failed to load resource: net::ERR_FAILED`. Root cause:
       prewarmEventImages() (public/index.html) fetches every event image
       (soulofmiami.org) in an unawaited background loop, and soulofmiami.org sends
       no CORS header, so the fetch is always blocked by the browser — not
       environment-specific, this would happen in any browser. It looked
       environment-specific and random because the Service Worker (public/sw.js)
       was intercepting those fetches in its own execution context (invisible to
       Playwright's page.route()) and masking the real CORS error behind a generic
       net::ERR_FAILED, landing on whichever test happened to be running when the
       async fetch failed. Fix: playwright.config.js now sets
       `serviceWorkers: 'block'` (stops the SW from masking real page-level
       network behavior in tests) and tests/fixtures.js stubs soulofmiami.org
       responses via `page.route(...).fulfill()` with a permissive CORS header
       (a `route.abort()` was tried first — it logs the identical net::ERR_FAILED
       line itself, so it didn't help). Two full `npm test` runs after the fix:
       287 passed, 0 failed both times. DONE 2026-07-19 — NOT a public/ asset
       change, no SW bump.
       NOTE — separate real product bug surfaced by this investigation: offline
       image pre-caching in prewarmEventImages() silently never works for ANY
       passenger (not just in tests) because of the same CORS block; the
       try/catch swallows it gracefully so passengers still see images fine
       online, they just never get cached for the offline/no-signal case. Not
       fixed here — needs its own item (likely: fetch with `mode: 'no-cors'` and
       cache the resulting opaque response, since `<img>` tags don't need CORS
       but `fetch()` does by default).

TEST SUITE & TAGS (Playwright)
------------------------------
Run all with `npm test`. TAGGED for fast targeted regressions:

    npm run test:index     # whole passenger app (index.html)
    npm run test:games     # all 5 games (logic + i18n + flows)
    npm run test:editor    # driver dashboard (editor.html)
    npm run test:backend   # Cloudflare Functions pure logic
    npm run test:weather / test:content / test:phone / test:rest  # index sub-areas
    npm run test:feedback  # ride feedback feature (tests/feedback.spec.js)
    npm run test:smoke     # fast critical-path subset
    npm run test:negative  # all failure-path tests
    npm run test:i18n      # translation / language-switch tests
    npm run test:units     # all in-browser pure-function unit tests

Tag taxonomy:
  PAGE  : @index @editor @games @backend  (+ sub-areas @weather @content @phone @rest @feedback)
  TYPE  : @unit (pure-fn) · @negative (failure paths) · @smoke · @i18n

Layout:
  - Pure logic lives in *-units.spec.js + backend.spec.js (base @playwright/test
    runner — CDN blips can't fail a pure assertion).
  - Behavioral E2E flows use ./fixtures, which FAILS on any console/page error —
    that strict gate catches silent breakage; keep it on flow specs only.
  - backend.spec.js imports functions/api/* helpers directly (test-only `export {…}`).
    No live network.

Freshness canary: tests/passenger.spec.js "published events are all upcoming"
goes RED once published events age past today — intentional, nudges a re-fetch
+ "Remove past" in the editor.

lines). No build step. SW caches files verbatim.

Decision (2026-05-28): KEEP the monolith. Don't migrate to a framework.

before reaching for React/Vue/Svelte/Vite. The cost of a build pipeline hugely
outweighs the benefit at this scale.

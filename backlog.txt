TEST SUITE & TAGS (Playwright)  — expanded 2026-06-01
-----------------------------------------------------
127 tests. Run all with `npm test`. The suite is TAGGED so you can run just the
section you touched instead of the whole thing (much faster regressions):

    npm run test:index     # whole passenger app (index.html)   — 56
    npm run test:games     # all 5 games (logic + i18n + flows)  — 27
    npm run test:editor    # driver dashboard (editor.html)      — 24
    npm run test:backend   # Cloudflare Functions pure logic     — 31
    npm run test:weather / test:content / test:phone / test:rest # index sub-areas
    npm run test:smoke     # fast critical-path subset
    npm run test:negative  # all failure-path tests
    npm run test:i18n      # translation / language-switch tests
    npm run test:units     # all in-browser pure-function unit tests
  (under the hood: `playwright test --grep @index`, etc. Tags can be combined,
   e.g. `npx playwright test --grep "@games" --grep-invert "@i18n"`.)

Tag taxonomy:
  PAGE  : @index @editor @games @backend  (+ sub-areas @weather @content @phone @rest)
  TYPE  : @unit (pure-fn, in-browser) · @negative (failure paths) · @smoke · @i18n

Layout:
  - Pure logic lives in *-units.spec.js (index-units, editor-units, games-logic)
    and backend.spec.js. These use the BASE @playwright/test runner so an
    unrelated background CDN blip can't fail a pure assertion.
  - Behavioral E2E flows (passenger/editor/rest/phone/weather/content/games/
    inactivity-tap) use ./fixtures, which FAILS the test on any console/page
    error — that strict gate is what catches silent breakage, so keep it on the
    flow specs only.
  - backend.spec.js imports the functions/api/* helpers directly (they now have
    test-only `export {…}`; Playwright's loader transpiles the ESM). No live
    network — pure parsing/mapping/allowlist logic only.

Freshness canary: tests/passenger.spec.js "published events are all upcoming"
goes RED once published events age past today — that's intentional, it nudges a
re-fetch + "Remove past" in the editor (see bug #19).

ARCHITECTURE NOTE
-----------------
Current: single-file index.html (~2800 lines including CSS + JS) and a
parallel editor.html (~1500 lines). No build step. SW caches the files
verbatim.

Decision (2026-05-28): KEEP the monolith. Don't migrate to a framework.
If/when navigation pain forces a refactor: split the JS into native ES
modules (no bundler) before reaching for React/Vue/Svelte/Vite. The cost
(build pipeline, learning curve, SW changes, more abstractions = more bug
surface) hugely outweighs the benefit at this scale.
